# v0.0.N — CI/CD, signed builds, release automation, e2e with tc

## Goal
Make pulsar release automation real: reproducible Nix builds, GitHub Actions CI, signed releases where credentials exist, and e2e tests that use tc to inject loss on Linux.

## In scope
- GitHub Actions workflow for build/test on Linux.
- Nix packaging and build path for releases.
- Signed build plumbing and release asset upload.
- e2e test harness using network namespaces and tc for loss/packet manipulation.
- Coverage reporting in CI where applicable.

## Out of scope
- Full GUI.
- Final 100% coverage guarantee in this step.
- Complete multi-platform signed release parity if credentials are missing.

## Acceptance
- CI builds and runs tests on push/PR.
- Releases can be produced from CI or locally via Nix.
- e2e tests exist and can simulate loss on Linux.
- Signed assets are produced when signing material is available.

## Notes
- Signing will be integrated once credentials/keys are available; until then we will prepare the pipeline and document the signing step.
- tc-based e2e tests require Linux and appropriate permissions; we will keep those tests Linux-specific in CI.
